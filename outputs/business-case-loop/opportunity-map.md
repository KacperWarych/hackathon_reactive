
## Latest user direction: shorten the sales cycle

The user prefers the current sales-cycle business case. This supersedes the agency-first recommendation and the requirement to investigate non-sales ideas each cycle. Paid-business viability remains primary. Agency pilot/price materials are parked alternatives, not the recommended offer.

Working thesis: help a seller move an active opportunity to its next decision by keeping changing buyer requirements, unresolved conditions and the next clarification visible with source evidence. Test a specific stage and bottleneck before claiming overall sales-cycle reduction.

Implemented foundation: dated retrieval, cited decision briefs, manual entry-and-refresh and version history. Unproven/missing: reliable account isolation, semantic resolution checks, automated monitoring and measurable sales impact.

Next priorities: identify a buyer segment and a recurring stage delay; replay a changed requirement through the existing report flow; compare against the seller's actual CRM/checklist and fresh stateless retrieval. Measure preparation time, relevant next-action quality, time from buyer update to human-reviewed follow-up, and days stalled at the chosen stage. Overall cycle length and win rate require real outcome data with deal complexity and other confounders considered. No measured uplift exists.

Automation pause state remains unchanged.

# Opportunity portfolio — broad challenge, 31 October 2026

## Decision

Reopen use-case selection. The sales blocker brief remains the nearest existing-data experiment, not the default winner. Compare three challengers: agency scope-change triage, technical-support handoff and engineering decision review. No candidate has validated customer demand or demonstrated a unique Reactor advantage.

The reusable kernel is: **new source → revised conclusion for a bounded case → inspectable evidence and version history**. Application state, event-triggered delivery and persistent model memory are distinct mechanisms and need separate evaluation.

## Three rankings, not one winner

**Hackathon demonstration priority (judgment):**
1. Agency scope triage: baseline says one language; later request asks for two; acknowledgment is not approval. Easy to understand, cheap to stage honestly.
2. Engineering decision review: new evidence defeats a scoped assumption, while unrelated decisions stay valid. Strong cause-and-effect explanation, more missing domain structure.
3. Support handoff: partial fix and recurrence show why latest-state reasoning matters, but good evaluation needs symptom and attempted-action detail.

Sales is the lowest-data-preparation option because the supplied synthetic corpus already exists. That is a practical advantage, not evidence of the best business.

**Business validation priority (judgment, conditional on access):**
1. Agency scope triage, if an owner can provide real briefs and change episodes.
2. Support handoff, if a team can provide permitted exports and compare its current tool.
3. Sales blocker brief, if sellers can show repeated context mistakes and an actual next action.

No willingness-to-pay evidence supports a market winner. Engineering review could move up if a reachable team supplies repeated invalidated decisions. Access to an actual pilot should outweigh these paper rankings.

**Reactive mechanism test priority (not proven Reactor advantage):**
1. Engineering assumption invalidation and research claim retraction: show precisely which dependent conclusion changes and which does not.
2. Support partial-resolution/reopening: maintain scoped state through contradictory outcomes and earlier failed attempts.
3. Agency scope/commitment changes: distinguish proposed, approved and withdrawn requirements.

A source log plus explicit state and stateless recomputation may win all three. Persistent Reactor memory is an experimental arm, not a prerequisite accepted by definition.

## Reviewable experiments created

`2026-10-31/candidate-replays.json` contains three explicitly synthetic scenarios with five events each: scope changes, support handoff and engineering decision invalidation. Each event specifies expected interpretation/action. The file was parsed and structure checked; no app/model execution occurred.

Common comparisons: (A) human + checklist/rules, (B) on-demand full-case analysis, (C) event-triggered stateless retrieval, (D) persistent Reactor with equivalent evidence. Include the buyer's actual incumbent tool where accessible. Measure source-supported state, missed changes, false review requests, wrong-case attribution, useful next action, human preparation/review time and full cost/latency. Record unavailable arms rather than inventing results.

Before model execution, add independent labels plus same-name/cross-case decoys, benign updates, late-arriving corrections and explicit retractions. Choose per-scenario acceptance gates in advance. A wrong authorized-change assertion, unsupported full resolution or fabricated dependency is a release-blocking fixture failure; passing a small fixture set is not population reliability.

## Reconciliation of agent disagreements

- The workflow and feasibility agents favor agency scope handling for a first accessible pilot, but neither found adoption/payment evidence. This is a hypothesis about testing friction, not a market conclusion.
- The reactive analyst favors engineering invalidation for exposing temporal reasoning. That does not prove a recurring buyer job or the need for persistent model history.
- Support is the strongest shared alternative, but embedded support tooling and data access may erase the opportunity.
- The existing sales dataset should reduce demo effort without dictating the product. Preserve it as a controlled comparator.
- All agents reject generic summaries, automatic status reopening, or reminders as sufficient differentiation. Semantic scope and useful decision change must be tested against strong baselines.
